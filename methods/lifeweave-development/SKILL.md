# 开发一项可接续的工作

先从已有事项读取当前目标和背景。新会话可用 `python scripts/lifeweave.py discover '目标'` 定位，再用 `continue` 回读；没有匹配时才创建事项。读 `knowledge --source lifeweave-project` 找当前项目规范，并用 `read-knowledge 'lifeweave-project:路径'` 读取必要正文。资料的实际版本、Git 仓库和未提交改动要核对；匹配推荐只是初筛，不证明已采用或适用。

用普通语言说清本次用户动作、期望结果、方案、代码责任和验收。只读问题直接回答，记录想法不启动代码执行。真正实施时先读相关源码，再在适当的隔离工作区修改、运行测试和必要页面验证；失败与未完成项保留。

平台启动的 Run 已保存输入与执行事件。若正在**现有 Codex 会话**直接开发，使用 `external-start <事项> --repo <Git目录> --summary <目标>` 关联这次外部会话；在真实完成方案、实施、验证或知识更新时，以 `external-report <事项> <sessionId> <phase> <摘要>` 上报。可附 `--knowledge <来源引用>` 与 `--check <实际检查>`。服务会读取当时 Git 提交和工作区差异，阶段及检查仍是外部会话的主动报告，不是自动捕获的内部 trace。命令不可用或服务不通时不要声称已登记；保留实际成果后补录，并标出未观测过程。

结束前更新受影响的当前说明，保留原始证据；再次从知识入口读取新版本，确认新会话能找到。把代码版本、实际测试与页面结果、未完成范围和下一步留在同一事项。运行成功、人工接受证据与用户接受事项分别表达；没有明确授权不自动合并其他代码仓或发布能力。
