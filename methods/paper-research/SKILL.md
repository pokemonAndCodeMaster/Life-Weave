# 论文与技术研究

先固定研究对象与本轮问题。通过作者、标题、官方论文入口与版本核对身份；简称有歧义时说明候选和差异，不自行选一篇替代。用户已提供明确链接时优先沿该来源。

在本轮隔离目录保存原始资料及来源清单（URL、标题、获取时间、版本/提交、读取范围）。优先官方论文、作者代码和补充材料。使用执行环境已有的网络与阅读工具；不要假定宿主的工具和 Skills 已自动接通。拿不到全文、图片、附录或代码时明确缺失与影响，不用摘要冒充已阅读全文。

根据用户问题组织连贯解释：研究解决的具体困难、为何采用该办法、关键机制和必要推导、训练数据和训练阶段、实验证据、局限，以及与用户当前工作的关系。区分作者主张、实测支持、代码实现和自己的推断。每个影响结论的事实给出可核对出处；解释比术语清单重要。

引用公式时定义符号并说明推导所需假设。Markdown 使用 `$...$` 和 `$$...$$`。需要图片时仅保存有来源的相关图到本轮工作目录，并引用相对 PNG/JPEG/GIF/WebP 路径；不能只输出开发机绝对路径或未经验证的远程图片。未取得图时用文字说明，不伪造原论文图。

有前轮成果和定位反馈时，先识别本轮需要修正的论点、材料或讲解方式，交付一份完整的新正文并指出修订处，保留仍然有效的结论；不要重复输出一份无关报告。目标冲突和无法验证的反馈需要说明，而不是偷偷修改已接受目标。

最终回答就是网页中的可读成果，使用 Markdown 提供完整正文与来源，不只回复文件路径或“已完成”。较大支撑材料另存目录，最终正文仍应能独立阅读。列出尚未解决的问题和有用的下一步。知识建议只作为候选；不修改知识原文，不推断用户已经掌握，不发送外部消息。
