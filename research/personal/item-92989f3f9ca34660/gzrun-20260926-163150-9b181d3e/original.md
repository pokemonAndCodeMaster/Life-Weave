1. **用户将看到的行为**

   展开“插件计划与实际调用”后，每条实际调用可独立展开，显示调用 ID、插件与操作、观测来源、状态，以及：

   - 调用记录中的固定插件版本和完整实现摘要；存在计划绑定时并列展示，便于核对。
   - 开始、结束时间；缺少结束时间显示“尚未记录结束”，不据此推断仍在运行。
   - 安全的输入引用、输出引用和错误说明；空引用显示“未记录”。
   - 可点击的 Run ID。没有 Run ID 的调用保留明细，不伪造运行关联。

   Run ID 点击后在组件内展开只读运行区域，显示同事项已有开发阶段、对应运行状态、原生会话 ID 和事件记录。不增加启动、取消、重试或接受操作。

2. **受影响模块和接口**

   修改范围为 `PluginProcess.vue`、必要的 `api/plugins.ts` 类型，以及新增 `PluginProcess.test.ts`。

   当前组件只汇总调用状态，而且仅按 `step_id` 匹配。实施时改为同时匹配事项、委托、计划和步骤，避免不同计划中的同名步骤串线；未匹配固定步骤的调用也提供独立明细。

   复用现有只读接口：

   | 接口 | 用途 |
   |---|---|
   | `GET /items/{itemId}/plugin-process` | 使用父组件已有过程数据 |
   | `GET /items/{itemId}/development` | 核对当前委托及方案、审阅、实施的 Run ID |
   | `GET /runs/{runId}` | 核对运行归属并读取状态 |
   | `GET /runs/{runId}/events` | 按游标读取原生事件 |

   组件从当前路由取得并校验空间、事项，与 `process.itemId` 一致后才读取。运行响应必须属于同事项；阶段名称来自委托记录，不能仅凭插件步骤推断。

   不修改父组件、路由、后端或数据库。现有运行弹窗含写操作，`RunTrace.vue` 会直接展示原始 payload，因此本组件采用自己的受限只读展示。

3. **历史、截断和安全边界**

   - 加载中、读取失败与“成功读取但没有固定计划”分别显示。当前空数据直接提示“接入之前”的判断需要修正；仅凭没有计划不能确定创建年代。
   - 有计划但无调用时显示“尚无实际调用记录”；条件步骤不解释为失败，未观测不解释为没有发生。
   - `truncated` 当前表示查询返回达到 200 条。文案应为“已达到返回上限，记录可能不完整”，调用数量标明为本次已返回数量；不能声称还有多少条，也不提示页面尚未提供的缩小查询操作。
   - `binding-drift` 当前表示**已返回调用的版本或实现摘要与固定计划不一致**，不代表已检查当前安装版本。保留历史调用，展示具体差异，不推断调用无效或业务失败。
   - 引用按已知字段和结构白名单展示，例如 Run ID、上下文版本、源码提交、方法及知识来源版本；未知字段不直接输出 JSON。自由文本错误采用已知错误分类和安全摘要，无法安全展示时明确提示已隐藏。
   - 原生事件展示序号、时间、来源、类型及可安全展示的结构化信息；不直接输出命令、工具输入输出、提示词或原始 payload。Vue 文本转义只能防止 HTML 注入，不能替代秘密过滤。

4. **实现顺序与风险控制**

   先完善调用匹配和类型，再实现逐条展开、引用展示及边界文案，最后接入 Run 只读区域和事件分页。

   Run 详情按点击加载。切换空间、事项、委托或所选 Run 时清空旧详情，并用请求序号忽略迟到响应；卸载后不更新状态。404、归属不符或事件读取失败只影响运行区域，已有调用明细仍可阅读。
